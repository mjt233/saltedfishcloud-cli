# CLI 命令命名与交互反馈调整设计

## 问题陈述

当前 CLI 在命令命名和错误反馈上存在几处不一致：

1. 用户可见文案里同时存在 `serviceUrl` / `apiTicket` 这类内部键名与 `--service-url` / `--api-ticket` 这类 CLI 风格名称，不利于理解与配置。
2. `ls` 命令必须显式传入路径参数，未体现“列根目录”这一常见默认行为。
3. 参数数量不满足时，当前主要返回 Cobra 默认错误，缺少该命令自身的参数帮助。
4. 命令名并未完全遵循统一的 kebab-case 风格，`remoteVersion` 与现代 CLI 的命名习惯不一致。

本次调整的目标是统一 CLI 对外语义，让命令命名、帮助文本、错误提示和 README 文档表达保持一致，同时不改变底层 service/client 的业务职责和配置优先级。

## 设计目标

- 所有用户可见命令名统一使用 kebab-case。
- 所有用户可见配置缺失提示统一使用横杠命名，并明确指导配置方式。
- 参数数量错误时直接输出对应命令的帮助文本，降低试错成本。
- `ls` 在无参数时默认作用于 `/`。
- 保持现有配置优先级、配置文件键名和服务层语义不变。

## 非目标

- 不保留 `remoteVersion` 的兼容别名。
- 不修改配置文件中的 JSON 键名，仍然使用 `serviceUrl` 与 `apiTicket`。
- 不引入自动命令归一化、模糊匹配或命令别名推断。
- 不调整 service、client 层接口或资源路径规则。

## 方案选型

### 方案 A：显式迁移到 kebab-case（采纳）

将对外命令名统一为 kebab-case，并同步更新帮助文本、README、测试与架构文档。参数错误帮助和缺失配置指引也一起收敛到命令层与配置层的明确职责内。

**优点**

- 规则直观，符合 Cobra/现代 CLI 的主流习惯。
- 文档、帮助、测试与实际行为一致，长期维护成本最低。
- 不引入额外隐式行为。

**缺点**

- `remoteVersion` 变更为 `remote-version` 是一次破坏性改动。

### 方案 B：保留旧命令作为兼容别名

可以平滑过渡，但会让帮助文案、测试和实际支持命令长期双轨运行，与“统一命名”的目标冲突，因此不采纳。

### 方案 C：做命令名归一化映射

例如把输入统一转换成 kebab-case 再匹配命令。该方案实现更隐式，调试与帮助体验较差，也偏离 Cobra 的常见用法，因此不采纳。

## 详细设计

### 1. 命令命名规则

- 根命令继续使用 `sfc-cli`。
- 所有子命令使用 kebab-case。
- 当前实际需要调整的命令为：
  - `remoteVersion` -> `remote-version`
- `ls`、`get`、`upload`、`rm`、`rename`、`cp`、`mv`、`version` 已满足当前规则，无需改名。

### 2. `ls` 默认参数行为

- `ls` 命令从“必须传入一个路径参数”调整为“路径参数可省略”。
- 当用户未传入参数时，内部按 `/` 处理。
- 帮助文本改为 `ls [path]`，并在说明中明确“默认列出 `/`”。

### 3. 参数数量错误时的反馈

在 `cmd/` 层收敛一个可复用的参数校验包装：

- 继续使用 Cobra 的参数数量语义（如 `NoArgs`、`ExactArgs`、`RangeArgs`）。
- 当校验失败时：
  1. 返回原始参数错误；
  2. 同时将当前命令的帮助文本输出到 `stderr`；
  3. 保持命令返回错误，便于调用方感知失败。

该包装应被需要参数校验的子命令统一复用，避免每个命令重复实现。

### 4. 缺失配置时的反馈

`internal/config.Load` 继续负责配置加载与必填校验，但对用户可见的报错文案调整为 CLI 风格表达：

- 缺失项显示为 `service-url`、`api-ticket`。
- 错误文本除列出缺失项外，还应说明可通过以下方式配置：
  - 命令行参数：`--service-url`、`--api-ticket`
  - 环境变量：`SFC_SERVICE_URL`、`SFC_API_TICKET`
  - 配置文件：`~/.config/sfc-cli/config.json`
- 配置文件示例仍说明 JSON 键名为 `serviceUrl`、`apiTicket`，避免用户误把文件键名也改成横杠。

### 5. 分层职责

#### `cmd/`

- 维护对外命令名和帮助文案。
- 负责参数数量错误时输出命令帮助。
- 为 `ls` 提供默认参数归一逻辑。

#### `internal/config/`

- 继续维护“命令行 > 环境变量 > 配置文件”的优先级。
- 继续使用内部键 `serviceUrl` / `apiTicket` 读取配置文件和环境变量映射。
- 负责生成带配置指导的缺失配置错误。

#### `internal/service/` 与 `internal/client/`

- 无行为调整。
- 保持当前资源路径解析、API 客户端构造与业务调用流程不变。

## 测试策略

需要更新或新增的测试覆盖点：

1. `ls` 在不传参数时默认请求 `/`。
2. `ls` 帮助文本改为 `[path]`，并体现默认值语义。
3. 参数数量错误时，输出包含当前命令的帮助文本，而不只是简短错误。
4. `remote-version` 可正常执行，`remoteVersion` 不再作为正式命令出现。
5. 缺失配置时，错误文本使用 `service-url` / `api-ticket`，并包含 flag、环境变量和配置文件路径指引。
6. 现有命令成功路径行为不受影响。

## 风险与约束

- `remote-version` 替换 `remoteVersion` 会带来一次性兼容性破坏，但这是用户确认接受的行为。
- 配置文件键名与用户可见错误文案刻意保持“内外不同名”：文件内部仍用 camelCase，CLI 输出使用 kebab-case。文档必须写清楚，避免造成误解。
- 参数错误时附带帮助文本需要避免吞掉原始错误，确保脚本调用时仍可感知失败状态。
